# CHANGESET-02 — Request-bound interaction attestation foundation

Target: `akamai-mfa-mcp 0.5.0-v2-dev`

## Purpose

Prove a stateless MCP server can receive a runtime-owned, per-request human
interaction reference without placing that value in the MCP tool schema.

The SDK contract used here is MCP Python SDK 2.2.0:

- tool functions may request an injected `Context`;
- `Context.headers` exposes the HTTP request headers for that MCP message;
- `Context.session_id` is `None` for stateless HTTP.

## Transport remains frozen

```text
transport="streamable-http"
json_response=True
stateless_http=True
```

No stateful troubleshooting mode is introduced.

## Attestation mode

Default:

```text
MCP_INTERACTION_ATTESTATION_MODE=disabled
```

Controlled validation:

```text
MCP_INTERACTION_ATTESTATION_MODE=request_header
MCP_INTERACTION_HEADER_NAME=X-MFA-Interaction
```

In request-header mode the MCP reads the configured header from the injected SDK
`Context`.

The interaction reference is:

- not a tool argument;
- not visible in the six public input schemas;
- not generated by the model;
- never logged;
- not persisted by MCP;
- not inferred from MCP session ID;
- treated as opaque runtime metadata.

Actor/session remain deployment-owned environment context in CS02.

## Tool behavior

The two read-only tools remain functional against API v2 and do not require an
interaction header.

The four prepare/reset tools remain fail-closed and make zero API calls.

They require a valid request-bound interaction only as a CS02 probe:

- missing/disabled attestation -> `interaction_context_unavailable`
- valid request header -> `not_available_in_cs02`

This distinction proves the header reached the actual tool request while
preserving zero destructive behavior.

## Important trust boundary

CS02 proves the MCP runtime mechanism, not final identity/authentication.

Production enablement still requires the host (LibreChat/integration layer) to
derive and inject this header from a real human interaction and to prevent an
untrusted caller/model from forging it.

## Explicitly absent

- API prepare calls
- API confirm calls
- API execute calls
- API retry calls
- destructive HTTP calls
- stateful MCP sessions
- LibreChat message-ID dependency
